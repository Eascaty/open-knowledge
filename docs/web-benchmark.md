# Web 大库逻辑基准

运行：`node scripts/benchmark-web > /tmp/web-benchmark.json`。只用 Node 内置模块，无网络、无真实资料、无数据库写入；不接受参数，也不读取 workspace。CI 的 Public Demo 作业运行同一命令，将 JSON 保留为7天构建附件。

## 固定样本与验证

`fictional-web-v1` 包含1,000/10,000张卡片，固定编号、10个方向、4个标签、6种可信状态及约千字的重复虚构正文。每个规模运行10种场景：搜索首页/次页、唯一命中、多词分散匹配、无命中、组合筛选、筛选项生成、复核排序、复核关键词和状态计数。期望编号、顺序和数量由固定编号规则计算，不使用待测搜索返回值作为答案；首次和每次计时运行后均校验，失败退出非零。

报告包含样本版本、字节数和 SHA-256；同版本数据应保持一致：

| 卡片数 | JSON 字节数 | SHA-256 |
|---|---|---|
| 1000 | 3023502 | d1df044a8ec398da7bb281075fe0129a72cee1859deae6f1fcfbde38418a0382 |
| 10000 | 30235002 | c4ca04f6e0b47195715df1c38c5a61041984f4411716dc9709c87d686e158905 |

每个场景先校验1次、预热3次，再计时20次。按最近秩法取 P50（第10个）及 P95（第19个）样本；不计生成资料和断言耗时。运行环境写入 Node 版本、系统、架构和 CPU 型号，不含用户名或主机名。测试不设跨设备的耗时硬门槛；CI 校验正确性并留下可比较的测量值。

## 2026-09-23 本机结果

同一台 Apple M3 / macOS arm64 / Node v22.12.0，先运行原搜索，再运行优化后版本，各一轮。优化将正文的全部关键词检查提前，不匹配的卡片不再转换标题、路径、标签和摘要；匹配规则、权重和排序不变，无缓存失效风险。

单位为毫秒；不同进程负载和运行次序会产生波动，不能把这次差值当作所有设备的性能保证。

| 1000 | combined-facets | 0.077 | 0.034 | 0.078 |
| 1000 | facet-options | 0.298 | 0.298 | 0.465 |
| 1000 | review-attention | 1.275 | 1.265 | 1.570 |
| 1000 | review-query | 2.811 | 2.716 | 2.867 |

| 10000 | common-first-page | 75.988 | 77.233 | 78.695 |

1万卡的唯一命中从81.545毫秒降至28.753毫秒，无命中从75.489降至21.926毫秒；全部命中的首页仍约77毫秒，复核队列未作性能调整。

## 尚未覆盖
