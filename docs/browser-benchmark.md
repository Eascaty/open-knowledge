# 大库桌面浏览器基准

在已安装 Chrome、Node 22+、Python 3.9+ 的开发机运行：

```sh
node scripts/benchmark-browser '/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' > /tmp/browser-benchmark.json
```

追加 `--constrained` 可运行受限窄屏配置：390×844、deviceScaleFactor=1、mobile=true、下载10 Mbps（1,250,000字节/秒）、上传2 Mbps、延迟80毫秒、CPU减速4倍。每个规模仍使用独立临时配置；加载等待上限为180秒，桌面模式保持60秒。参数只是 Chrome 模拟条件，不代表任何具体手机或网络套餐。

Linux 将参数替换为 Chrome 可执行文件的绝对路径。脚本不安装或升级依赖；CI 使用运行器预装 Chrome/Node，版本写入报告，缺少前置条件会失败。Public Demo 作业保留 JSON 报告7天。

## 测量方法

复用[建站基准](site-benchmark.md)的 `fictional-site-v1` 千卡/万卡私密样本。在全新临时目录生成网站，使用仅绑定127.0.0.1的服务打开；每个规模启动独立 Chrome 临时配置，无界面桌面视口1280×900，禁用浏览器缓存并绕过 Service Worker。不会读取用户浏览器配置、真实知识库或数据库，结束或失败时关闭子进程并清理临时文件。

- 页面打开：从导航起点到应用 `aria-busy=false` 后两个动画帧的时间；含本机数据传输、解析、初始化和帧调度，不含建站及 Chrome 进程启动。每个规模单次冷配置导航，磁盘/操作系统缓存不保证冷启动，不能解释为 P50/P95。
- 搜索：通过真实输入框触发 input 事件，计时到两个动画帧之后；覆盖30条首屏、唯一命中及无结果，每种连续3次，报告原始样本和中位数。搜索框展开不计入计时。此为 DOM 事件驱动的无界面验收，不是人工键盘或屏幕呈现延迟测量。
- 正确性：验证页面没有致命加载错误和未捕获异常，已加载 canonical 数据，没有外部页面资源；检查首屏30个固定编号、唯一目标编号和零结果。
- 内存：记录页面就绪后与完成搜索后的 `JSHeapUsedSize`，并附 DOM 计数；不强制垃圾回收，不是峰值、保留堆或进程总内存。DOM 计数可包含尚未被垃圾回收的旧节点，不能据此判断泄漏。

报告不记录临时路径、端口、用户名或真实资料。测量时启用 Chrome 的后台网络抑制选项，但页面资源检查不等同于抓包证明整个浏览器进程零网络。

## 2026-09-23 本机结果

Apple M3、macOS arm64、Node v22.12.0、Chrome 153.0.8010.53。以下为最终脚本的一轮测量；毫秒为耗时，MiB为二进制内存单位。

| 卡数 | 页面就绪 ms | 常见搜索中位 ms | 唯一命中中位 ms | 无结果中位 ms | 打开后堆 MiB | 搜索后堆 MiB |
|---|---|---|---|---|---|---|
| 1000 | 166.9 | 21.5 | 26.8 | 28.5 | 8.79 | 8.70 |
| 10000 | 383.2 | 69.9 | 27.4 | 26.6 | 77.75 | 101.80 |

万卡样本的 canonical 和搜索 JSON 分别约56 MB和52 MB，通过本机回环网络加载，未压缩。公网或手机上的传输与内存成本可能明显更高，这组结果不能当作真实手机或远程站点承诺。

## 2026-09-26 受限窄屏结果

同一台 Apple M3、macOS arm64、Node v22.12.0、Chrome 153.0.8010.53，使用上述受限配置。每个规模一次页面加载、每类查询3次，保留原始耗时而不设置跨设备速度门槛。

| 卡数 | 页面就绪 秒 | 常见搜索中位 ms | 唯一命中中位 ms | 无结果中位 ms | 打开后堆 MiB | 搜索后堆 MiB |
|---|---|---|---|---|---|---|
| 1000 | 9.62 | 69.9 | 24.6 | 15.6 | 8.70 | 8.75 |
| 10000 | 88.07 | 287.9 | 114.0 | 110.0 | 75.93 | 80.80 |

两种规模的搜索首屏滚动到底后，输入框与关闭按钮仍在视口内，输入框位置不变，结果区可见可滚动，页面没有横向溢出；这些几何断言也用于桌面模式。全部18次搜索结果编号/数量校验通过，无致命加载错误或外部页面资源。

万卡在此配置约88秒才就绪，说明当前全量 canonical 和搜索 JSON 的传输成本是远程大库的明显瓶颈。此结论只针对固定未压缩虚构样本；此表采集时尚未实现压缩传输、按需正文或索引分片，不据此承诺公网万卡体验。本轮后续已实现 gzip 兼容读取并用相同样本对比，结果见下节。

CI 额外运行受限配置，并保留独立 `browser-constrained` JSON附件7天。页面响应、布局或结果错误会使作业失败；低速条件的正确结果也必须等待完成，不能把超时当作通过。

## gzip 兼容读取复验（2026-09-26）

支持解压的浏览器现在优先请求三份 gzip 副本，原 JSON 仍保留用于旧浏览器、旧包、错误和离线回退。追加 `--uncompressed` 可在独立测试页面禁用解压能力，强制走原 JSON，便于同构建、同 Chrome 比较；不改用户浏览器设置。报告包含 `transfer_mode` 并断言三份压缩数据确实被使用，或回退模式未请求压缩副本。

当前安装的 Chrome 为153.0.8010.54，上一节原始测量为153.0.8010.53，因此本轮又在当前版本补跑原 JSON 回退对照。下载10 Mbps、80毫秒延迟、4倍CPU减速、390×844不变。

| 卡数 | 原 JSON 就绪秒 | gzip 就绪秒 | 原 JSON 数据传输字节 | gzip 数据传输字节 |
|---|---|---|---|---|
| 1000 | 9.633 | 1.082 | 10826480 | 127654 |
| 10000 | 88.800 | 2.600 | 108156113 | 1244755 |

两组都通过固定编号、唯一目标、空结果、滚动控件与无横向溢出断言。表中传输量是三份数据的 Resource Timing transferSize 之和，含响应头估值，不含页面壳和后台请求；每组单次冷配置导航，未做统计显著性推断。

压缩只改变传输表示，浏览器仍需完整解析知识数据。样本大量重复文字，压缩率远高于许多真实资料；不据此预测真实库改善比例。公开 PWA 仍预缓存原 JSON，本轮结果针对私密静态样本的首次就绪时间，不代表公开离线安装的总流量。

## 完成边界

L15 现已覆盖固定样本的搜索/复核逻辑、静态建站、桌面浏览器打开与搜索、JavaScript 堆快照。已补充网络和 CPU 限速模拟，但尚未覆盖真实手机、低内存设备、进程峰值内存、热启动/PWA缓存和多轮统计；也不代替已有的无障碍与窄屏功能验收。基准不上传站点、不放宽公开发布门禁，不根据单轮结果自动改架构或加缓存。
